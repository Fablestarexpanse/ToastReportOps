## 1. Executive summary

**The mission loop is real and running end-to-end**: ingest (19 active sources)
→ verify (extract/embed/corroborate/attribute) → watch (new-start detection) →
draft (cited, evac-verbatim, approval-gated) → publish (static site). All six
workstation modes are live; 88 tests green; zero dead jobs at audit time.

**The three findings that matter most:**

1. **Backups are local-only.** Litestream replicates to `data/replica/` — the
   *same disk, same house*, and the house is in a fire zone. This is the single
   highest-stakes gap in the whole system. (§4, R1)
2. **The trust loop — pillar #4 of the architecture — is unbuilt.**
   `source_stats` has 0 rows. Nothing measures source lead time, accuracy, or
   yield; tier promotions can't happen. The tiers are currently static labels,
   not earned trust. (§4, R4)
3. **Official evacuation-zone data is absent.** Evac facts arrive only via news
   and CAP — the dedicated evac aggregation layer (Genasys/Zonehaven) is still
   blocked on the operator's TOS review. For a Paradise-based operator, this is
   the mission-critical data gap. (§4, R2)

## 5. Maximizing the tool — priority order

**Quick wins (minutes each, do first):**
- **Q1 — FIRMS map key** (free registration → `.env`): satellite hotspot
  detection, often the earliest automated signal for new starts. Feeds the
  watch board with a T1 sensor signal.
- **Q2 — Cloudflare Pages token**: makes the public site *actually public*;
  PSPS degraded mode becomes meaningful.
- **Q3 — `gh auth login`**: verify CI is green on every push.
- **Q4 — DB hygiene reset** (optional): clears the 11 pre-gate foreign facts +
  test artifacts now that all gates are in place.

**Highest-value engineering (no external blockers):**
1. **B2 offsite backup + restore drill** (R1) — do before anything else.
2. **Alert rules + native notifications** — "new start / evac within N miles of
   Paradise → notify" is the single most personally valuable feature for the
   operator; pairs with a Tauri tray build.
3. **Trust/source-stats loop** (R4) — nightly job computing lead-time vs CAL
   FIRE, supersession-by-higher-tier rate, and yield; surfaces in SOURCES; makes
   tier promotion real. This is also what makes "catch what others miss"
   *measurable* (lead-time is the metric).
4. **Fire weather** (RAWS/HRRR, free APIs) — the WEATHER tab + Red Flag context;
   predictive, not just reactive.
5. **Corroboration tuning + replay eval** (R6, R7) — sharpen the verify stage.
6. **Adjudication triage** (R5) — expiry + bulk actions + watch-board folding.

**Blocked on operator decisions (queue these decisions):**
- Evac layer TOS review (R2) — highest mission value of the blocked set.
- Scanner audio: own SDR (trunk-recorder; ~$40 hardware, cleanest legally) vs
  OpenMHz vs Broadcastify (TOS-problematic).
- ADS-B: adsb.fi/airplanes.live fair-use vs own receiver.
- X/Facebook publisher credentials; FB app review has lead time — start early.

## 6. A daily operator routine (using what exists today)

1. **Morning (2 min)**: open `ToastReport.cmd` → OPS. Scan intake for overnight
   T1/T2 facts; check map deltas; glance at WATCH for corroborating candidates.
2. **On a new start**: WATCH → promote when 2+ sources agree (or CAL FIRE
   lists it). OPS → select incident → verify the ledger. NEWSROOM → draft from
   ledger → edit → approve → publish. The site updates itself.
3. **Midday hygiene (5 min)**: adjudication strip — attach the obvious, ignore
   the rest (until R5 lands); point-at-URL anything interesting from your own
   browsing.
4. **During an active local incident**: narrow intake to Butte sources +
   keyword; draft updates on a "since last update" window; publish on a cadence.
5. **Weekly**: SOURCES — add any feed you found yourself reading; prune
   zero-yield ones (Guardian/KTLA/TimesSD are on probation per poll logs —
   they poll fine but haven't yielded CA fire facts yet; keep 2 more weeks).
