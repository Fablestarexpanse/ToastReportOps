# Full Project Audit — 2026-07-22

Professional audit of Toast Report OPs: documentation review, build/test
validation, functional, security, code-quality, architecture, database,
performance and testing review, with safe fixes applied the same day.
Conducted with four parallel specialist reviews (documentation accuracy,
security, code quality/dead code, database/migrations) plus direct
validation runs; every finding below was verified against code before
being reported, and every fix re-verified afterward.

## 1. Executive summary

**Overall condition: strong.** The codebase is unusually disciplined for its
size — parameterized SQL throughout, a real SSRF gate, secret scrubbing in
logs and backups, an enforced append-only ledger, prompt-injection fencing,
propose-never-act AI flow, all containers bound to 127.0.0.1, and a 444-test
suite that passes (unit + HTTP integration). **Production-ready for its intended deployment** (a
single-operator localhost workstation) with the fixes applied today.

Most serious findings (all fixed same-day):
- **Stored XSS (High)** — map tooltips rendered external strings as raw
  HTML; the worst path let any stranger on the public Meshtastic MQTT
  broker run script in the operator's browser, which fronts the
  unauthenticated API. 12 interpolation sites escaped via a shared escaper.
- **Unsanitized markdown → HTML (Medium)** — draft preview/export/site
  passed raw HTML from python-markdown to the browser; a hostile article
  echoed into a draft became live markup *before* the human-review gate.
  All three render sites now sanitize through `nh3`.
- **SSRF DNS-rebinding TOCTOU (Medium)** — the fetcher validated the
  resolved address, then httpx re-resolved to connect. A post-connect peer
  check now closes the window.
- **Documentation drift (High for a handoff)** — README claimed "Phase 0
  not started" for a fully built system; 12 files corrected.

Remaining risks are listed in §8; none is Critical.

## 2. Project overview

- **Backend:** Python 3.11, FastAPI, SQLite (WAL, STRICT tables, enforced
  FKs, append-only facts ledger with supersession), structlog, httpx,
  Pillow; job queue + scheduler processes.
- **Frontend:** Next.js 15 (Turbopack) + React 19 + TypeScript, Leaflet
  (bundled), inline-style single-file mode components (house style).
- **AI:** in-stack Ollama container (OpenAI-compatible), versioned operator
  -editable prompts, embeddings via sqlite-vec.
- **Services (Docker Compose, all localhost-bound):** api, worker,
  scheduler, llm, mesh, litestream, searxng, ldr.
- **Auth:** none by design — single operator, every published port binds
  127.0.0.1; the browser origin is the trust boundary (why XSS mattered).
- **Publishing:** site generator + Bluesky/X/Facebook/Telegram adapters,
  credential-gated, human approval enforced by a DB state-machine trigger.
- **Testing:** pytest (444 tests incl. HTTP integration), ruff, tsc, eslint.

## 8. Remaining issues (priority order)

1. ~~Next.js 16 upgrade~~ — done 2026-07-22, zero vulnerabilities remain.
2. **Supersession anti-join redesign** (M5) — replace `NOT IN (SELECT
   supersedes…)` with a `superseded_by` column or an `is_current` flag when
   season-scale facts slow the pickers. *Needs a migration; not urgent.*
3. ~~Integration tests~~ — done 2026-07-22: tests/integration/ drives the
   real app over HTTP (draft lifecycle, publish guard, sanitizer,
   activity-check through the actual job queue and worker).
4. **Capacity plan for raw_blobs/facts** (M7) — season-end disk estimate
   and optional cold-tier offload. *Operational.*
5. **Telegram user-id allowlist** (L2) — only if the ops chat ever becomes
   a group.
6. **`GET /sources/suggestions` → POST** (L3), **picker consolidation**
   (L5), **aircraft index-friendly time filters** (L6) — minor cleanups.
7. **Accessibility** — the UI is a dense operator console (small mono
   fonts, click-target spans, no keyboard navigation). Acceptable for its
   single expert user; a rework would be needed before any multi-user or
   public exposure. *Noted, not scheduled.*
